# Optional asset packages

Opt in with `MiniGameBackend.setDeferredAssetPackages(Map<String, List<String>>)`. The default empty map retains the existing three mandatory packages. Each key is a unique lowercase package name; `engine`, `game`, and `assets` are reserved. Selectors are complete logical file paths, directory prefixes ending in `/`, or file-stem prefixes ending in `.` (for an atlas and its PNG). Derive application declarations from its asset catalogs, not duplicated runtime lists.

The build validates selectors against internal/classpath files in `preload.txt`, rejects unmatched selectors and conflicting ownership, then moves payloads after blocked-extension renaming. Each optional package lives at `optional/<name>/<original relative path>` and has an asset-only `game.js`. The common `assets/asset-packages.json` maps logical file paths to package names. `preload.txt` and `rename-map.json` remain common and retain logical names. Source asset folders are never moved.

`MiniGameAssetPackages.isMissing(path)` reports whether the containing optional package has completed `wx.loadSubpackage` in this running version. It does not use manifest membership, unversioned user-storage copies, or a previous run's cache as readiness. The platform can satisfy a load from its own versioned cache. `load(newlineSeparatedPaths, completion)` deduplicates overlapping package requests, reports failure once, and removes failed pending entries so callers can retry. Thirty seconds without progress times out; a late callback cannot finish a later attempt. Startup on a host without `wx.loadSubpackage` shows an update-WeChat message and an Exit button before starting any downloads. It never claims moved files are ready or enters an unrecoverable retry loop.

Internal/classpath `exists()` and `length()` reflect readiness, and reads before readiness fail rather than caching a missing texture. Directory listings still describe the full logical manifest, including deferred files. Local user files are not mapped into optional packages. Supported packaged audio paths use the same package root. The AssetLoader waits for optional files before completing listener-based loads.

The application must resolve required saved assets before creating synchronous readers such as TextureAtlas. A valid saved selection should not be replaced because a download fails. Keep the loading screen and offer retry. Optional UI entry requests may offer cancel after gameplay has started. JavaScript completion occurs between frames: post UI mutations through `Gdx.app.postRunnable`. This backend owns readiness and physical paths; application-owned presentation stays out of the loader.

Tests: `:backends:backend-minigame:check` covers layout, renamed payloads, conflicts, empty/default configuration, concurrent requests, failure/retry, timeouts, fresh-runtime readiness, and release-compiled Java/JS file reads. Node mocks do not replace Android/iOS/PC WeChat checks.

Consumers adding the new API must first publish this backend revision to Maven Local with `:backends:backend-minigame:publishToMavenLocal`, then rebuild their mini-game. The current shared catalog uses `1.5.4-SNAPSHOT`; record the tested backend commit alongside the consumer change. An older snapshot lacks the new build/runtime API and fails compilation.
